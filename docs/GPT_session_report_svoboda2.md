## Публичные серверы NL/FI/US (только что реализовано для 2.0.7)

Источник: публично опубликованный репозиторий Delta-Kronecker/Cloudflare-Warp
(коллективные публичные WARP-конфиги, используются многими клиентами).

Встроено в APK под атрибуцией:
- NL — 9 конфигов (nl/nl2/nl3.tribukvy.ltd), FI — 3 конфига (fi.tribukvy.ltd),
  США/anycast — 3 (engage.cloudflareclient.com, страна измеряется после подключения).
- В UI (раздел AWG → «ПУБЛИЧНЫЕ СЕРВЕРЫ · NL/FI/США») одно нажатие подключает выбранный конфиг;
  страна выхода измеряется после подключения и пишется в prefs (для AUTO-приоритета).

Честные ограничения, которые я зафиксировал в UI:
- это коллективные публичные identity, доступность/скорость не гарантированы;
- приоритет AUTO по измеренной стране, не по метке хоста.

## Открытые вопросы к тебе (вопросы из чата, по порядку)

   встраивать коллективные публичные конфиги в APK с атрибуцией, или лучше сделать
   только импорт файлов/подписок? Какие риски стабильности ожидаем?
2. Релиз 2.0.7: опубликовать на GitHub (как 2.0.6, до-Play-Protect-эпохи) — стоит ли
   уже выпускать с учётом того, что на устройстве тесты частично не прогнаны
   (телефон был занят пользователем), либо ждать полного смоук-прогона (NL/FI/US public servers,

3. Бенчмарк: DIRECT-baseline и макро-оценка по категориям — достаточная ли методология
   для сравнительного теста 42 стратегий; сколько staged-попыток практически оптимальны
   (3→10→20)? Что ещё обязательно добавить, прежде чем публиковать результаты?

   недоступности DC AUTO предпочитает AWG/WARP, иначе — честное сообщение, без
   бесконечных переподключений. Достаточно ли этого, или нужен прямой учёт Telegram Proxy

5. GeoHide (DPI-1.6A — static DNS map для HEV на малом списке доменов) — делать ли в 2.0.8
   после смоук-теста 2.0.7, или сначала Telegram/AUTO стабилизировать на устройстве?
6. Что для 2.0.8 принципиально важнее: (а) починить защиту сокетов ciadpi от VPN для
