## 3. Архитектурная позиция (FINAL): DPI как последний аварийный интернет-маршрут

`ConnectionResetException` от Telegram DC не превращает рабочий интернет-маршрут в `NoWorkingRoute`.
Две независимые оценки соединения:

| Проверка | Что доказывает |
|---|---|
| Data Plane **через TUN** (реальный HTTPS, не только SOCKS-порт DPI) | Интернет работает |
| Telegram DC | Telegram недоступен |

Сценарии:

| Сценарий | Результат |
|---|---|
| A: Data Plane OK + Telegram DC OK | CONNECTED / HEALTHY |
| **B: Data Plane OK + Telegram DC FAIL** | **CONNECTED · LIMITED** (интернет есть; Telegram отмечен отдельно; AUTO НЕ запускает бесконечный failover только из-за Telegram) |
| C: Data Plane FAIL | Candidate rejected, продолжается поиск маршрута |

- Настройка `autoTelegramViaVpn=true` сохраняет смысл («Telegram должен работать через VPN»), но её невыполнение **не лишает** пользователя работающего интернет-маршрута. UI должен честно показать ограничение Telegram.
- Подтверждение Data Plane — только реальным HTTPS через TUN (не только `socks` data-plane OK).
- Успешный общий Data Plane не вызывает повторный AUTO-цикл.

## 4. RC3 — два НЕЗАВИСИМЫХ изменения (не смешивать в один патч)

**Изменение A — DPI emergency fallback:**
- DPI может быть последним кандидатом после отказа остальных.
- Telegram DC — отдельный критерий качества, не блокирующий выбор DPI.
- Ограниченное подключение получает отдельный статус (CONNECTED · LIMITED).
- Успешный Data Plane не вызывает повторный AUTO-цикл.

**Изменение B — Cancellation и lifecycle:**
- Исправить блокировку отмены (CONNECTING → «ОТМЕНА»).
- Отмена инвалидирует старую сессию; старая coroutine не выбирает следующий кандидат.
- Операции с TUN/backend остаются сериализованными.
- Владение сессией и повторные AUTO-запуски — под контролем.
- Реализацию `b7c19a0` переносят только после нового архитектурного ревью.

A и B реализуются как отдельные, диагностируемые изменения.

## 5. Обязательный сценарий приёмки RC3

1. Все публичные endpoint недоступны.
2. WARP handshake не проходит.
3. DPI SOCKS Data Plane проходит, Telegram DC возвращает reset.
4. AUTO **выбирает DPI**.
5. Chrome открывает сайт через TUN.
6. UI показывает ограниченную работоспособность (CONNECTED · LIMITED), без бесконечного CONNECTING/backoff.
7. После восстановления Telegram DC статус обновляется без ненужного переключения маршрута.

Отдельно проверяем: отключение во время probe / handshake / backoff.

Кандидаты в RC3-ветку: по одному PR/коммиту на A и B, с ревью между ними.
