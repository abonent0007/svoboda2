# Свобода 3.0 — экспериментальный проект (ветка `experiment/svoboda3`)

**Статус:** заготовка под продолжение в другом агент-аккаунте. Рабочая линия «Свобода 2.0»
(ветка `hardening-2026-11-19`, версия 2.0.9) остаётся отдельно и не затирается.

- **Пакет:** `svoboda3.runet.abonent0007`
- **Название на устройстве:** «Свобода 3.0»
- **Версия:** 3.0.0 (versionCode 300)
- **База:** код 2.0.9 (hardening) с переименованием пакета/неймспейса и заготовкой под userspace-роутер.

## Зачем

В 2.0.x — один активный транспорт (AWG/WARP/DPI) на весь VPN; per-app распределение
возможно только «туннель или direct» (VpnService allow/deny). В 3.0 цель: **мульти-роутер трафика**
— разным приложениям разные upstream'ы одновременно, в рамках одного TUN.

## Ограничения (важно, иначе сломается работающее)

1. **Один VpnService на пользователя.** Android не даёт два параллельных VPN. Ядро роутинга
   не может иметь свой tun рядом с текущим: только замена или тот же TUN.
2. **VpnService allow/deny — один список на туннель.** «Каждому приложению свой upstream»
   требует, чтобы ядро само принимало пакеты из TUN и решала по UID/пакету.
3. Смешивать ядро роутинга с текущей рабочей схемой «в лоб» нельзя — только за флагом
   и с мгновенным откатом (см. `VpnController.applySplitTunnel`, единая точка инъекции списков).

## Структура заготовки

- `app/src/main/java/svoboda3/runet/abonent0007/router/RouterBridge.kt` — JNI-мост к ядру (заглушка).
- `third_party/router-libs/` — сюда кладутся собранные ядра (`librouter.so` / `libmihomo.so` / `libsing-box.so`)
  по ABI: `arm64-v8a`, `armeabi-v7a`, `x86_64`.
- Контракт моста: `start(context, config, tunFd)` / `stop()` / `stats()`; ядро принимает
  **существующий** TUN fd от VpnService.

## Порядок работы в другом аккаунте

1. Выбрать ядро (mihomo/Clash.Meta, sing-box, Xray) и лицензию (фиксировать в этом файле).
2. Собрать `.so` под Android (gomobile / NDK), положить в `third_party/router-libs/<abi>/`.
3. Реализовать `RouterBridge` (заменить заглушку), добавить упаковку в `jniLibs`.
4. В `VpnController.applySplitTunnel` — опциональный режим роутера: вместо allow/deny отдавать
   TUN fd ядру; upstream'ы: direct / DPI-socks / AWG / WARP; правила по UID/пакету.
5. Приёмка: одновременная работа двух приложений через разные upstream'ы; откат на 2.0-схему
   одним переключением; замеры скорости против текущей схемы.

## Правила

- Не ломать текущую схему: 2.0.9 — рабочая; 3.0 — эксперимент.
- Любое изменение маршрутизации — за флагом и с откатом; не публиковать без проверки на устройстве.
- Прогон 2.0.9-матрицы (см. `docs/DEVICE_RC_2026-11-19_evidence/`) — база для сравнения производительности.
