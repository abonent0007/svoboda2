# «Свобода 2.0» — кандидаты для 2.0.8 (исследование, ничего не внедрено)

Дата: 2026-11-17. Источник: `confeden/Nova-Android`, отдельная лента `confeden/nova_updates`.
Проверено самостоятельно: `opera_endpoints.json` и `proton_nodes.json` — действительные
публичные файлы (opera обновлён 2026-11-17T14:43:14Z, "surfeasy-discover").

## Источники

1. **Opera endpoint feed** (`nova_updates/opera_endpoints.json`) — 14 публичных endpoint
   областей EU (5), AM (7), AS (2); видно как регион Americas (AM), не гарантия US-IP.
   Полезно только для отдельного Opera-транспорта через opera-proxy/surfeasy.
   Требует HTTP CONNECT/прочей логики `surfeasy` и НЕ является AWG/WARP-туннелем.

2. **Proton public nodes** (`nova_updates/nova_android/proton_nodes.json`) — 100 серверов
   по странам (CA13 CH8 JP12 MX9 NL12 NO8 PL6 RO8 SG12 US12). Только входы: IP, страна,
   город, public key сервера. Подключение требует собственной регистрации устройства
   в Proton VPN API (`/vpn/logicals?Tier=0`); иначе не подключиться. Это **отдельный
   транспорт**, не список для AWG.

3. **WARP verified seeds** (assets в Nova) — 50 IP:port endpoint, 45 IPv4 + 5 IPv6,
   15 разных приватных ключей (clients), один общий server public key, режим
   `warp-awg-exact`. Можно брать **только IP:port** в качестве кандидатов для нашего
   собственного `WarpProfileFactory`. Взять как есть нельзя: клиентские приватные ключи
   принадлежат Nova и их нельзя использовать в нашем приложении.

4. **DNS** — Yandex (`77.88.8.8`, `77.88.8.1`, `77.88.8.88`, `77.88.8.2`),
   Quad9/Google/Cloudflare дубли, `195.208.5.1` (RU, claimed) / `195.208.4.1` (unverified);
   DoH-эндоинты из RETIRED_BUILT_IN (автор Nova намеренно убрал) — не восстанавливать
   автоматически.

## Принцип (базовый)

- Публичные **данные** (endpoint, считаемые серверы) — можно брать как factual references.
- Чужие **идентичности** (клиентские приватные ключи Nova) — не берём.
- Лента Opera/Proton — материалы отдельного open-source проекта; использовать можно
  как публичные данные, атрибуция — в документации; переиспользовать их код не нужно.
- Ничего из этого не имплементируется до завершения 2.0.7.

## План (после решения о релизе 2.0.7)

1. (П1) Opera-транспорт: отдельный slot в AUTO с Surfeasy-прокси; endpoint pool из
   `opera_endpoints.json`; кэш 3 часа; проверка реального HTTPS через кандидата.
2. (П2) Proton: отдельный вариант туннеля через регистрацию собственной identity DES
   устройства (`/vpn/logicals?Tier=0`); оценить объём реализации; не смешивать с AWG.
3. (П3) WARP: расширить пул endpoint публичными IP из seeds, только как кандидаты
   для наших собственных WARP-генерированных профилей.
4. DNS: добавить Yandex DNS в каталог (с пометкой «только через RU-маршрут»), не вместо
   существующих; новые резолверы — только после замера на обеих сетях.

## Чего принципиально не делаем

- Не берём клиентские приватные ключи из чужих выдающихся файлов, даже «публично» лежащих.
- Не копируем код Nova ничего (GPL/иное лицензирование неизвестно без проверки).
- Не публикуем до решения по 2.0.7.
- Не смешиваем это с текущей 2.0.7 — она заморожена.
